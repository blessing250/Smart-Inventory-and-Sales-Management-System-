## Reuse and migration impact

Keep the feature pages, components, Tailwind styles, accessible form patterns, PDF styling references, stable IDs and the PostgreSQL snapshot exporter. Treat the current route shapes, Zod validations, business SQL, and Vitest scenarios as parity references. Java must implement authorization, validation, transaction orchestration and report queries independently before replacing a route. Leave browser purchase drafts and optional expense attachments intact.

The main risks are duplicate writers, changed rounding or expense classification, incomplete import of linked records, changed password or session handling, and a premature cutover. The [migration plan](ARCHITECTURE_MIGRATION_PLAN.md) defines the sequence, acceptance gates and rollback.

## Authentication milestone update

The [Milestone 3 compliance matrix](docs/SPRING_CATALOG.md) covers the current Spring catalog, legacy dependencies and cleanup decisions.

Spring Security now has owner bearer authentication and recovery endpoints in the [Spring module](backend/spring), isolated from the live app. [Flyway V2](backend/spring/src/main/resources/db/migration/V2__owner_authentication.sql) adds one owner slot, a session registry, reset-token digests and security audit events. Next.js authentication and the SQLite business path remain authoritative.

### Why the Vitest counts differ

The historical 45-test run included five cases in the retired `app/lib/inventory-calculations.test.ts` fixture. Git retains the five original cases for profit, stock in, stock out, oversell rejection and sale subtotal. They were removed with the unused prototype helper during earlier cleanup, which reduced the suite to 40. The PostgreSQL backend work then added one cross-database owner recovery case, bringing the current Vitest suite to 41. It was a removal and an addition, with no difference in how Vitest counts the remaining cases. This milestone preserves the active suite. Java tests have a separate Maven count.
